1. Hermes platform — context

Hermes is a multi-tenant communications platform Vocalcom deploys across several cloud instances. The objects that matter for WhatsApp:

  • Instance — independent Hermes deployment. We run several in parallel.
  • Customer — billable tenant living on one instance.
  • Application / use case — Hermes-platform features (SpeedToLead, Outbound, Inbound, Email, Chat …). Customers subscribe to none, one, or many.
  • Campaign — owned by a customer, defines the phone numbers it sends from.
  • Number — MSISDN attached to a campaign.

2. The four Telnyx WhatsApp objects

ObjectEndpoint rootRole
WABA/v2/whatsapp/business_accountsMeta business identity — one per customer.
Phone Number/v2/whatsapp/phone_numbersMSISDN registered to a WABA.
Messaging Profile/v2/messaging_profilesWebhook URL + spend cap + features.
Template/v2/whatsapp/message_templatesPre-approved Meta template per WABA.
Send call carries only from + to + whatsapp_message. Telnyx resolves WABA and profile from the from number.

5. Send messages

One endpoint covers every WhatsApp message type. Discriminator: whatsapp_message.type.

CallEndpoint
SendPOST /v2/messages/whatsapp
RetrieveGET /v2/messages/{id}
  • Inside 24 h window: text, image, video, document, audio, sticker, location, contacts, interactive, reaction.
  • Outside 24 h window: approved template only.
  • Idempotency: handled in Hermes (no client-supplied ID on Telnyx).
  • Tracking field: biz_opaque_callback_data is echoed on DLR webhooks.

8. Customer-scoped views

Telnyx API keys are account-wide. Hermes is the gateway — customers never hold a Telnyx key.

  • Customer authenticates to Hermes.
  • Hermes resolves customer_id from session.
  • Hermes queries its own CustomerPhoneNumber + MessageDispatch filtered by customer_id.
  • Customer sees only their numbers, templates, messages.
